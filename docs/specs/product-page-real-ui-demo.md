## Problem Statement

站点目前用文字、静态图谱故事和一个浅色风格化示意 demo 来讲产品理念。示意 demo 的问题是**不像产品**：访问者看到的不是 CoResearch 的真实界面，而是站点自创的面板布局。看演示的人无法建立「这就是我要装的哪个软件」的认知，演示的说服力因此打折——对比参考产品（CrommaCode）的产品页：它直接把真实应用界面做成深色 mock 并播放运行动画（消息流式出现、计数器跳动、面板逐项点亮），访问者立刻知道产品用起来是什么样。

此外，演示混在长首页中段，没有一个专门回答「这个产品是什么、跑起来什么样」的产品页。

## Solution

新建 **/product 产品页**：一整页深色的 CoResearch 真实界面复刻 mock——完整三栏布局（左侧导航与项目树、顶栏、中间对话流与输入框、右侧「对话研究图谱」与方向详情卡），在 mock 数据驱动下**自动循环播放一次完整研究运行**：研究者在输入框里输入模糊兴趣、会话出现在项目树、方向树在图谱里生长、方向被标记「当前」、详情卡字段逐项填充、文献卡滑入、缺口与候选方法经审查确认。全程有「运行感」——消息流式出现、处理计时器跳动、上下文百分比增长、节点逐个点亮。

首页现有浅色演示区退役，替换为一个静态入口卡（真实 UI 复刻的一帧静态画面 + 「观看运行演示」链接）指向 /product，避免两套 mock 叙事并存。诚实标注保留：页面明确说明界面与内容均为 mock、不代表已上线功能、候选结论须核验。

## User Stories

1. As a 首次访问者, I want 从首页进入一个专门的产品页， so that 我能不被其他叙事打断地回答「这个产品是什么、跑起来什么样」
2. As a 首次访问者, I want 产品页里的演示长得和真实 CoResearch 界面一致（深色、三栏、同样的面板名与措辞）, so that 我看完演示就能认出并上手真的产品
3. As a 首次访问者, I want 滚到演示区就自动播放一次完整研究运行, so that 我不注册、不操作也能看懂产品的工作方式
4. As a 首次访问者, I want 看到研究者在输入框里逐字输入一句模糊兴趣并发送, so that 我理解使用产品从一句话开始
5. As a 首次访问者, I want 看到发送后左侧项目树里出现新会话条目, so that 我感知到「运行」真的发生了而不是幻灯片
6. As a 潜在用户, I want 看到右侧图谱里候选方向节点逐个出现、随后选中方向被「当前」标记高亮, so that 我理解 Explore 是帮我定位细分方向
7. As a 潜在用户, I want 看到方向详情卡的简介/开放式问题/代表性工作字段逐项填充, so that 我理解每个方向自带可追溯的结构化摘要
8. As a 潜在用户, I want 看到文献卡（标题、作者、期刊年份、代表/Abstract 标签）滑入详情卡并可看到「打开」入口, so that 我理解证据是真实论文而非编造摘要
9. As a 潜在用户, I want 看到「已处理 for Xs」处理行里的计时器跳动, so that 我对运行节奏有真实感
10. As a 潜在用户, I want 看到输入框的上下文百分比随阶段推进增长, so that 我理解会话上下文是产品在管理的资源
11. As a 潜在用户, I want 看到候选缺口以「尚待确认」语义出现在详情卡与对话流中, so that 我不会误以为产品替我断言研究空白
12. As a 潜在用户, I want 看到跨领域机制作为新节点连入图谱并附带迁移前提, so that 我理解跨领域迁移是候选而非结论
13. As a 潜在用户, I want 看到审查结论逐项给出通过/待议, so that 我理解候选方法要过新颖性与可行性检查
14. As a 潜在用户, I want 最后看到研究者确认候选方法、图谱出现候选方法节点, so that 我理解关键决策始终由人做
15. As a 潜在用户, I want 各 Agent 的分工通过对话流与图谱动作呈现（Lead 协调、已处理行、审查消息）, so that 我在真实界面词汇里理解多 Agent 协作而不是看一个产品里不存在的状态条
16. As a 忙碌的访问者, I want 演示自动循环, so that 我中途才注意到它也能从头看起
17. As a 想细看的访问者, I want 悬停时动画暂停、移开后继续, so that 我能停下细看当前画面
18. As a 想跳着看的访问者, I want 阶段说明文字、上一/下一阶段按钮与阶段跳转选择器, so that 我能按自己的节奏看
19. As a 使用键盘的用户, I want 左右方向键切换阶段, so that 我无需鼠标也能操作
20. As a 开启「减少动态效果」的用户, I want 直接看到最终完整状态的静态画面, so that 我既不被动画打扰也能获得同样的信息
21. As a 小屏/移动端用户, I want 演示窗口按屏幕缩放、三栏折叠为纵向堆叠且保持可读, so that 我在手机上也能看懂流程
22. As a 无障碍用户, I want 演示区有清晰的 aria 标签、当前阶段可被读屏感知, so that 我能非视觉地跟随流程
23. As a 慢网络用户, I want 演示不依赖大体积媒体资源（无视频/图集/WebGL）, so that 产品页随页面快速加载
24. As a 切换标签页后回来的用户, I want 演示在页面不可见时暂停, so that 回来时画面不跳变、资源不浪费
25. As a 谨慎的研究者, I want 页面明确标注「界面与内容为 mock、不代表已上线功能、候选结论均须核验」, so that 我不会误信演示中的研究结论
26. As a 想深入了解的访问者, I want 产品页与 Explore / Deep Dive 设计文档互链, so that 我能从演示自然走到设计文档
27. As a 从首页过来的访问者, I want 首页的旧演示位置出现一个真实 UI 风格的静态入口卡与链接, so that 我能发现产品页且首页加载更轻
28. As a 仓库维护者, I want 演示阶段状态仍是纯函数且可逆, so that 我能回归测试且修改阶段定义不怕破坏其他阶段
29. As a 仓库维护者, I want mock 文案与界面结构集中声明, so that 我调整叙事或改 UI 文案不用碰动画机制代码
30. As a 仓库维护者, I want 深色复刻样式隔离在演示窗口内, so that 站点浅色主题与既有章节不受影响且不引入主题系统
31. As a 仓库维护者, I want 演示不引入新的运行时依赖, so that 包体积和构建复杂度不增加

## Implementation Decisions

### 页面与导航

- 新增 /product 路由：服务端组件页面壳（标题、一句话定位、演示区、控制条、免责说明、文档互链）+ 客户端演示组件。
- 站点头部导航新增「产品」入口（/product）；文档页与首页适当位置可互链。
- 首页旧「产品使用演示」章节退役移除，原位置放置静态入口卡：新演示的一帧静态画面（深色窗口缩略）+「观看运行演示」链接。不再保留旧浅色 demo 组件与其场景定义，避免两套 mock 叙事并存。

### 复刻的界面布局（完整三栏，深色）

以产品真实界面截图为蓝本，mock 窗口内从左到右：

1. **左侧导航栏**：产品 logo 与名称；主导航（首页、搜索、论文雷达、浏览）；「新建会话」按钮；项目区（项目名 → 会话列表 → 画布节点的树状结构）；底部用户条。演示期间此栏有两个活动点：发送问题后新会话条目出现；画布节点计数随阶段增长。
2. **顶栏**：会话页签（面包屑式）、点赞数、功能图标簇——全部静态装饰，保证观感一致即可。
3. **中间对话流**：方向提及卡（@细化方向 chip + 本轮的出发点）、处理行（「已处理 for Xs」计时器）、研究者与 Research Lead 的消息气泡、审查/确认卡片；底部输入框区（模型选择器、+任务、上下文百分比、发送按钮——静态但上下文百分比由应用器驱动增长）。
4. **右侧「对话研究图谱」面板**：点状网格画布上的方向树（复用并适配现有树声明：根兴趣 → 候选方向 → 聚焦分支 → 证据叶 → 待核实缺口 → 跨域机制 → 候选方法），「当前」徽标标记选中方向；画布下方为方向详情卡（标题、简介、开放式问题、代表性工作、已有证据、尚待确认）与文献卡（标题、作者、期刊年份、代表/Abstract 标签、「打开」按钮）。

**保真决策**：产品真实界面没有 Agent 状态横条与 Idea State 计数条，因此不再复刻这两个站点自创面板——Agent 分工改由对话流（Lead 消息、已处理行、审查消息）与图谱动作呈现；Idea State 的已知/未知/Intent 演化改由方向详情卡字段填充与树生长表达。叙事信息不丢失，界面词汇全部来自产品本体。

### 视觉与样式

- 深色主题 token（底色、面板色、强调色、徽标色）按产品截图取样为常量，写进演示专用样式；不引入主题系统、不改站点浅色主题。
- 演示窗口以桌面应用窗框（交通灯圆点 + 窗口标题）包裹，圆角大阴影浮在页面浅色背景上——深色只存在于窗口内部，天然隔离。
- 全部用站点既有技术栈（Tailwind 工具类 + 一份演示专用小 CSS）实现；无新运行时依赖、无图片/视频/WebGL 资源。

### 动画架构（继承既有 seam，扩展状态）

沿用「场景定义 → 舞台应用器 → 静态 React 壳」三层架构与既有纪律（帧内无 React 协调、无 DOM 查询、paintKey 缓存、rAF 帧间隔钳制、IntersectionObserver + visibilitychange + 悬停 + reduce 四重门控）：

1. **场景定义（纯函数，扩展）**：在既有 7 阶段叙事骨架（发起 → Explore → Deep Dive → Gap Finder → Innovator → Reviewer → Revision）上重排舞台。ScenarioState 扩展出新产品面板字段：对话流式进度（逐字/逐条，取确定性子串，禁用 Math.random / Date.now）、处理计时器值、上下文百分比、详情卡各字段的填充进度、文献卡到达、树可见集合与「当前」徽标位置、侧栏会话条目与画布计数。整数 progress 严格等于该阶段 settled 状态；同一 progress 永远得到同一状态、采样方向无关（既有可逆性契约不变）。
2. **舞台应用器（扩展写入目标）**：在既有写入（data-phase、消息/卡片可见性、树元素显隐、焦点标记位移、清单状态）之上，增加写入流式文本子串、计时器/百分比文本、详情卡字段显隐与「当前」徽标位移、侧栏会话条目显隐。paintKey 键随新增字段扩展。
3. **静态 UI 壳（重写）**：按上述三栏布局实现 mock 窗口；所有动画帧可变元素挂 data 属性由应用器独占写入，React 只渲染一次。
- 时钟、循环、手动步进、reduce/矮屏降级、键盘导航、aria 直播区等容器行为与既有演示容器相同，随演示组件迁移到产品页。

### 阶段脚本（7 阶段，沿用现有叙事节拍，总时长约 35–40 秒循环）

1. **发起**：输入框逐字输入模糊兴趣 → 发送 → 左侧项目树出现新会话条目 → Research Lead 回复建议先 Explore。
2. **Explore · 定位方向**：图谱画布出现三个候选方向节点 → 「当前」徽标落到选中方向 → 对话流出现方向确认卡，详情卡标题与简介填充。
3. **Deep Dive · 重建脉络**：处理行出现且计时器跳动 → 详情卡「开放式问题 / 代表性工作」逐项填充 → 文献卡滑入。
4. **Gap Finder · 候选缺口**：「已有证据」填充后「尚待确认」出现待核实缺口，对话流同步缺口消息（标注待核实）。
5. **Innovator · 跨领域迁移**：跨域机制节点连入图谱，详情卡出现迁移前提清单（部分满足、一项待验证）。
6. **Reviewer · 审查**：审查卡片逐项给出 通过/通过/待议。
7. **Revision · 演化与确认**：图谱出现候选方法节点，对话流出现研究者确认动作，上下文百分比停在终值；回绕到阶段 1 时 UI 复位无跳变。

### 性能与降级纪律（继承）

- 不在动画帧内进行 React 协调或 DOM 查询；CSS transition 承担入场动效，帧循环只翻状态；
- 深色窗口在大面积深底上注意对比度（正文至少达到 WCAG AA）；
- 无媒体资源；环境级 rAF 饥饿下表现为暂停而非状态错乱。

## Testing Decisions

- **好的测试只断言外部行为**：场景采样契约（确定性、可逆、钳制、阶段键完整）与应用器的 DOM 效果（属性、class、文本内容），不断言内部结构。
- **Seam 不变**：仍是「场景纯函数层 + 应用器层」两个既有 seam；新增面板字段纳入同一测试脚本，不新建测试机制。
- **扩展既有测试脚本**（沿用 TypeScript 转译到临时目录 + node:assert 模式）：
  1. 转译场景定义与应用器模块，零语法错误；
  2. 采样确定性与可逆性（正向/反向同值同状态）；
  3. 阶段边界：整数 progress 等于 settled 状态；NaN / 负数 / 超界落到首/末阶段；
  4. 阶段 id 唯一、时长为正、每阶段覆盖扩展后的全部状态键（含流式进度、计时器、上下文百分比、详情卡字段、徽标位置、侧栏条目）；
  5. 流式文本契约：给定阶段内进度，输出文本等于全文案的确定性前缀；阶段 settled 时等于全文案；
  6. 树声明完整：边的两端都是已声明节点，各阶段树集合 id 均已声明；
  7. 应用器在假元素上：写入 data-phase、切换新增元素的可见性 class、写入流式文本与计数值、「当前」徽标 transform 更新；相同状态重复调用零 DOM 写入（paintKey 生效）；
  8. reduce 路径：终态渲染等于完整显示状态。
- **prebuild 串联**：既有 prebuild 继续运行研究故事测试与本测试（改指迁移后的场景/应用器模块），任一失败阻断构建。
- **Prior art**：现有 product-demo 测试脚本与研究故事测试脚本（同一转译 + 假元素断言模式）。
- **浏览器手测清单**（不入自动化）：滚入自动播放、悬停暂停、手动步进与跳转、循环回绕无跳变、reduce 静态终态、三栏在小屏的堆叠可读、深色窗口与浅色页面的边界干净。

## Out of Scope

- 真实后端 / API / 数据集成：演示全部为 mock 内容，不发起任何真实研究任务；
- 可交互输入：演示窗口不可输入、不可点击进入真实功能，只能观看与步进；
- 产品页的其他章节（定价、下载、Roadmap 等）；
- 开屏类动画（logo 粒子形变、星空流星等 WebGL/Canvas 效果）；
- 音频旁白与字幕音轨；
- 国际化与多语言文案（mock 文案仅中文）；
- 站点整体深色模式：深色只存在于演示窗口内部；
- 演示内容的录屏导出或分享卡片生成。

## Further Notes

- **呈现参考**：CrommaCode 产品页的观感目标——真实应用窗口 + 持续运行感（流式消息、计数器、面板逐项点亮）；CoResearch 的对应物是产品截图中的对话流与对话研究图谱面板。
